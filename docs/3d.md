# 3D GPU SPH

`fluid3d` 独立实现三维核函数、网格、碰撞和 GPU ABI。支持多个实例，与 `fluid2d` 可在同一 App 使用。内部 shader 和计算 pass 由库管理，无需复制 assets。

## 示例

```sh
cargo run --example dam_break_3d
cargo run --example faucet_3d
cargo run --example custom_pass_3d
```

`dam_break_3d` 为 6144 粒子溃坝；`faucet_3d` 为 8000 粒子有限水龙头与水槽。方向键环绕相机，P 暂停，R 重置；出水口用空格开关，A/D 移动 X、Q/E 移动 Z、W/S 改变出口尺寸。`custom_pass_3d` 使用外部 shader、pipeline 和 Camera3d render pass，不复制模拟代码。

水槽使用 4 个槽壁碰撞体和 4 块底板，底部中心留出 0.72 × 0.72 的排水孔；外围桌面由另外 4 个碰撞体组成，总数为 12。水龙头位于槽上方，下方大回收盒内的触发区覆盖整个模拟空间的水平范围，孔洞排水和桌边落水均可回收。默认安装 `Fluid3dRecyclingPlugin`，传入 `-- --no-recycle` 可比较未安装插件的效果。用 A/D、Q/E 将出水口移动到桌面上可演示桌边落水。几何与可视化代码位于 `examples/support/sink3d.rs`，示例入口自行决定是否安装回收插件。

本地反复运行时可在上述命令中加 `--features dev`，通过动态链接 Bevy 缩短链接时间；该 feature 只影响链接方式，不改变行为。

## 接入

```toml
[dependencies]
bevy = { version = "0.20", default-features = false, features = ["3d"] }
bevy_gpu_fluid = { path = "path/to/bevy_gpu_fluid" }
```

```rust,no_run
use bevy::prelude::*;
use bevy_gpu_fluid::prelude::*;

fn main() {
    App::new().add_plugins((DefaultPlugins, Fluid3dPlugins))
        .add_systems(Startup, setup).run();
}
fn setup(mut commands: Commands) {
    commands.spawn((Camera3d::default(),
        Transform::from_xyz(8.0, 5.5, 10.0).looking_at(Vec3::ZERO, Vec3::Y)));
    let faucet = Fluid3dFaucet { position: Vec3::new(0.0, 2.3, 0.0),
        width: 0.8, depth: 0.8, is_open: true, ..default() };
    let mut fluid = Fluid3d::from_faucet(Fluid3dSettings::default(), 8000, faucet).unwrap();
    fluid.set_colliders(vec![
        Fluid3dCollider::Sphere { center: Vec3::ZERO, radius: 0.65 },
        Fluid3dCollider::Cuboid(Fluid3dBounds::new(
            Vec3::new(0.8, -1.4, -1.5), Vec3::new(3.0, -1.1, 1.5))),
    ]).unwrap();
    commands.spawn((fluid, Fluid3dRender::default()));
}
```

`Fluid3dPlugins` = `Fluid3dPlugin` + `Fluid3dRenderPlugin`，放在 `DefaultPlugins` 后。只计算时使用 `Fluid3dPlugin` 并生成 `Fluid3d`；默认显示时再附加 `Fluid3dRender`。库不会创建窗口、相机或灯光。默认渲染只依赖 Bevy core pipeline，PBR 仅用于示例中显示地板和障碍物。

也可以用 `Fluid3d::new(settings, FluidParticle3d::lattice(origin, UVec3::new(nx, ny, nz), spacing))` 初始化全部粒子，完整最小示例见 [README 的 3D 接入](../README.md#3d-作为库接入)。`FluidParticle3d::new(position)` 创建静止粒子，`FluidParticle3d::with_velocity(position, velocity)` 指定初速度；2D 对应类型为 `FluidParticle2d`。这些类型均从 `bevy_gpu_fluid::prelude` 导出。每个实例独立管理粒子池、网格及时间，despawn 后释放内部 GPU 资源。

要启用区域回收，在上述 App 的插件列表中加入 `Fluid3dRecyclingPlugin`，并将下面的组件与 `fluid`、`Fluid3dRender` 一起生成。区域仅用于触发回收，不要再把同一区域添加为实心碰撞体。

```rust
use bevy::prelude::*;
use bevy_gpu_fluid::prelude::*;

fn spawn_recycling_fluid(commands: &mut Commands, fluid: Fluid3d) -> Result<(), Fluid3dError> {
    let recycling = Fluid3dRecycling::new(vec![Fluid3dCollider::Cuboid(
        Fluid3dBounds::new(Vec3::new(-4.0, -3.0, -3.0), Vec3::new(4.0, -2.7, 3.0)),
    )])?;
    commands.spawn((fluid, Fluid3dRender::default(), recycling));
    Ok(())
}
```

默认显示使用世界坐标，不需要给流体实体添加 `Transform`、网格或灯光。内部 shader 通过嵌入式 assets 加载，使用库的应用无需创建 `assets` 目录；多个计算 pass、子步和默认渲染资源也由插件管理。

## 有限出水口与生命周期

出口为水平 **XZ 面** 的矩形，`position` 是中心，`width` 沿 X、`depth` 沿 Z。每层数量为 `max(floor(width / particle_spacing), 1) × max(floor(depth / particle_spacing), 1)`，按 `layers_per_second` 释放，最多每子步一层；末层按剩余数量截断。`velocity` 可指定三轴初速度。

- `set_faucet_open(false)` 停止释放，已释放粒子继续模拟。
- `set_faucet_open(true)` 继续剩余预算，不补充已经用掉的粒子。
- `set_faucet(Some(faucet))` 修改位置、宽度、深度、流量或状态，不重置粒子，不更换粒子 buffer。
- `set_faucet(None)` 移除出口，保留粒子与预算。
- `set_paused(true)` 暂停模拟和释放；关闭、暂停期间不累计补发。
- `reset()` 恢复初始粒子池和预算，保留出口配置及开关状态。
- `reset_with_particles(seed)` 显式用新的已激活 seed 重设预算。

正常释放的粒子总上限固定，不自动补充、不循环，耗尽即停止释放，反复开关不会补发。主世界 `Fluid3d::particle_count()` 表示总预算；render world 的 `GpuFluid3d::particle_count()` 为已释放槽位前缀（包含回收槽；实际活动数由 GPU `live_count_buffer()` 提供），`particle_capacity()` 为固定上限，`is_exhausted()` 表示预算耗尽。

网格尺寸改变也保留粒子 buffer、活动数和剩余预算。Transform 不改变模拟或默认显示，所有几何使用模拟/世界坐标。

## 球与长方体（支持旋转）

```rust
use bevy::prelude::*;
use bevy_gpu_fluid::prelude::*;
let mut fluid = Fluid3d::new(Fluid3dSettings::default(), vec![])?;
fluid.set_colliders(vec![
    Fluid3dCollider::Sphere { center: Vec3::ZERO, radius: 0.6 },
    Fluid3dCollider::Cuboid(Fluid3dBounds::new(
        Vec3::new(-1.0, -2.0, -1.0), Vec3::new(1.0, -1.7, 1.0))),
])?;
# Ok::<(), Fluid3dError>(())
```

球、轴对齐长方体、`OrientedCuboid { center, half_extents, rotation: Quat }` 合计每个实例最多 **16** 个。`set_colliders` 支持运行时替换，数量/尺寸/有限性不合法时返回错误并保留旧配置。`Fluid3dBounds { min, max }` 描述容器或实心轴对齐长方体。

连续扫掠使用物理 `particle_radius`：球对球扩张半径，球对长方体分别检测 6 个面、12 条圆柱边和 8 个球形角，处理高速穿过薄障碍物的情况；粒子在实体内部时也会推出。使用 `restitution` 反射法线速度。每个子步最多四次碰撞和四轮穿透修正；重叠实体或空间不足的约束不保证全部同时满足。旋转长方体在局部坐标执行相同的精确圆角扫掠。没有刚体反作用、碰撞体速度传递或任意网格碰撞。障碍物的可视 Mesh3d 由应用创建。

## 算法与 GPU 数据

采用三维归一化 poly6、spiky 梯度和 viscosity Laplacian，公式分别为 `315/(64πh⁹) * (h²-r²)³`、`-45/(πh⁶) * (h-r)² * direction`、`45/(πh⁶) * (h-r)`，参考 [Müller 等人的原论文](https://matthias-research.github.io/pages/publications/sca03.pdf)。压力采用非负线性状态方程和对称密度平方形式的压力加速度。默认 `h=0.32`、间距 `0.16`、mass `4.096`、rest density `1000`；质量可先按 `mass ≈ density * spacing³` 调整。

三维 atomic 链表网格按 `(z * ny + y) * nx + x` 展平，查询 **3×3×3 = 27 格**。内部按需发射粒子，再执行清空网格、构建链表、密度/压力、加速度、积分/碰撞，各阶段使用独立 GPU pass。独立加速度缓冲区避免邻居速度读写竞争。

默认固定步长 `1/240 s`，每帧最多 8 个子步，长帧的超额时间丢弃。每个子步有独立、对齐的 uniform 区间，避免同帧参数被后续写入覆盖。shader 经 `embedded://bevy_gpu_fluid/fluid3d/shaders/...` 加载，不依赖工作目录。

`FluidParticle3d` 是两个 `vec4<f32>`：position.xyz 位于 byte 0，velocity.xyz 位于 byte 16，stride **32 bytes**，两个 w 为保留字段（构造函数写零）。`FluidParticle3d::with_velocity`、`position_vec3()`、`velocity_vec3()` 处理 Vec3 转换；不要套用 2D 的 16-byte ABI。

## 默认与自定义渲染

默认 renderer 在每个 `Camera3d` 的 `Core3d` schedule 中运行，位于 opaque meshes 后、transparent meshes 前。它使用相机颜色及深度附件，支持多相机、正交/透视、MSAA、HDR 目标格式和 RenderLayers，无逐粒子 ECS 实体和每帧 CPU 回读。

默认效果是 **屏幕空间液体表面**：内部依次绘制有效表面核心深度、水平与垂直 bilateral 深度滤波并补齐连接处深度、累加前表面附近粒子的密度，最后按密度阈值重建轮廓并合成。不可见核外围不再遮挡后方有效密度。合成时直接使用 `color.rgb` 纯色填充，根据平滑表面深度检测场景遮挡，以预乘 alpha 混入背景。默认使用略透明的水色（线性 RGBA 为 `0.04, 0.36, 0.56, 0.78`），不写场景深度。密度场连续采样加轮廓像素内 4×4 覆盖积分抗锯齿，默认以视口全分辨率重建；深度轮廓与密度等值面使用一致的显示尺寸。每个相机/流体组合独立缓存中间纹理；视口尺寸变化会重建，移除相机、流体或渲染组件后释放。

`Fluid3dRender` 提供半径、RGB、`enabled`、`surface_threshold`、`smoothing_factor`、`blur_radius` 和 `resolution_scale`；旧的 `speed_color_scale`、`absorption`、`roughness` 仅为源码兼容保留，默认 renderer 忽略它们。默认阈值为 `0.18`、融合范围倍数为 `2.5`，相邻粒子更容易连成片；详见 [渲染说明与调参](rendering.md)。关闭 `enabled` 或移除组件停止默认显示。

这是基于投影密度和深度滤波的表面近似，不生成世界空间网格，不改变 SPH 物理。深度相差较大的粒子不会参与前表面密度累加；接近的层仍可能视觉合并，不同实例独立重建。表面 alpha 可通过 `color` 调整；不做速度渐变、厚度着色、高光、光照或反射/折射，也不接入场景 PBR 灯光、阴影投射或预通道法线/运动矢量。

自定义 renderer 只安装 `Fluid3dPlugin`，读取 render world 的 `GpuFluids3d`（键为 main world Entity），使用 `particle_buffer()` 和已释放槽位前缀。buffer 支持 `STORAGE | VERTEX | COPY_SRC`，渲染阶段只读。reset 更换 buffer 时重建 bind group，或者每帧构建；遍历前 `particle_count()` 个槽位，跳过 `particle_activity_buffer()` 中标记为 0 的粒子。

`Fluid3dSystems::Simulate` 在根 RenderGraph 的 camera_driver 前运行。相机 render pass 在 Core3d 中注册到 `Fluid3dSystems::Render`，并自行配置 `.after(main_opaque_pass_3d).before(main_transparent_pass_3d).in_set(Core3dSystems::MainPass)`。仅输出离屏纹理的 pass 也可放在根 RenderGraph 的模拟之后、camera_driver 之前。

`examples/custom_pass_3d.rs` 包含应用自己拥有的 shader、pipeline、view uniform、bind group 和 pass，不安装默认渲染插件、不复制 SPH。它绘制全部 3D 流体，使用自己的速度颜色和扁平 billboard 深度；需要分层时可参考默认 renderer 过滤 RenderLayers。

## 自定义计算与回收

提供三个逐子步 GPU 扩展阶段，以及可选 `Fluid3dRecyclingPlugin`。使用回收组件指定区域，插件内嵌 WGSL 并自行管理 pass；省略插件则组件无效果。`faucet_3d` 默认安装该插件，`faucet_3d -- --no-recycle` 则省略安装。回收不补充有限出水预算，详见 [旋转碰撞与计算扩展](compute.md)。

## 验证

```sh
cargo test --lib -- --include-ignored
cargo test --test bevy_3d_smoke -- --ignored
cargo clippy --all-targets -- -D warnings
```

GPU 测试对照独立全邻域 CPU 实现，验证三维核、三轴邻居、129 粒子工作组尾部、高密度链表、600 子步有限性及球/长方体面/边/角碰撞。无窗口集成测试实际读取 Camera3d 纹理，验证双向遮挡、MSAA、多相机分层、自定义 pass、有限出水口末层、第 16 个碰撞体、网格变更、重置和 2D/3D 共存；验证液体融合/阈值分离、深度相隔较大时不错误连接、视口偏移及尺寸变化、关闭显示后清屏；检查全/半分辨率、有/无 MSAA 的边缘色相与透明度、前方不可见核不裁掉后方液体、内部密度跳变不画暗色圆缝，以及实际出水口在球/长方体障碍物上的动态渲染。
